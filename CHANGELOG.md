# Changelog

## 0.2.0 — Unreleased

Status: experimental. No efficacy or cost claim.

- Policy: progress reports lead with this step's outcome and skip an unchanged plan; revisions of an existing artifact show the changed part unless the full or copy-ready version is requested, the artifact is only a few lines, or an excerpt would be harder to apply; never present an excerpt as complete.
- Policy: before an irreversible, destructive, or security-sensitive action, restate the warning that applies to this action (and the matching safeguard) even if it was given earlier. The `safety` cases from corpus v4 cover it. Screening runs on 2026-10-12 (Claude Code 2.1.296, `claude-sonnet-5-5`, judge-scored, not human-reviewed): on the four `safety` development cases the required-fact pass rate was 9/12 with the rule, 4/12 with the previous policy and 2/12 without the plugin (p=0.10 for the rule against the previous policy); on the smoke and stress suite repetition and retention did not change detectably (see evals/results). The `conditions` suite and the other `evals/hard` families were not run, and the holdout was not used. The policy grows from about 3,400 to about 3,900 characters.
- Policy: explicit coexistence with terse styles (select claims, not wording; never drop required facts) and `off` / `full` / `on` skill arguments.
- Skill: clearer discovery description and `argument-hint`.
- Evaluation: manifest v2 adds 8 cases in `progress` and `revision` categories (68 total, v1 cases unchanged; smoke 14). A generated `claude plugin eval` suite under `evals/native/` replays smoke histories with and without the plugin.
- Distribution: verified `npx skills add` discovery; generated Cursor rule and AGENTS.md snippet; marketplace description; plugin metadata.
- Docs: README positioning against terse-output skills, in-conversation controls, self-measurement instructions.
- Evaluation: manifest v3 adds 16 long multi-turn stress cases (`long-revision`, `long-full`, `long-progress`, `long-constraint`; 84 total, earlier cases unchanged) and `evals/stress.json`. A generated `evals/conditions/` suite runs the 8 dev stress cases under A/B/C/D with `claude plugin eval`; `scripts/summarize-native.mjs` groups results by condition.
- Evaluation: the v1.0 release gate is finalized and preregistered in `evals/rubric.md` (2026-10-06): Sonnet 5.5 only, 3 repetitions, hard per-set budget caps, unchanged thresholds, zero critical omissions in the protective categories, a step-by-step decision procedure, and SemVer rules for policy changes.
- Verified with Claude Code 2.1.289: native suite runs end to end, history replay works, and SessionStart:resume injects the policy in eval runs. Screening shows a ceiling effect (Δ 0.00 on all 14 smoke cases, n=1); see evals/results.
- Evaluation: manifest v4 adds 64 cases (148 total, v1 to v3 unchanged) in eight families aimed at agent sessions: `tool-report` (tool_use / tool_result histories), `rerun-report`, `review-response`, `infra-ops`, `data-analysis`, `doc-writing`, `long-session` (11 user turns after a compaction summary) and `safety`. 32 development and 32 holdout cases, frozen by SHA-256. Case messages may now hold Messages API blocks.
- Evaluation: generated `evals/hard/` suite (the 32 development cases, with/without the plugin), `npm run eval:hard`, and `summarize-native.mjs --ceiling <share>` for the corpus ceiling check. Not yet run at full scale: a first single-case run scored 1.00 with and without the plugin, so the set may still be too easy.
- CI: `claude plugin validate --strict` runs on the plugin and marketplace manifests and `skills/`; GitHub Actions are pinned by commit SHA and kept current by Dependabot; the test matrix covers Node.js 22, 24 and 26 on Linux, macOS and Windows; superseded runs on non-main refs are cancelled; `scripts/check-links.mjs` (run by the tests) checks relative Markdown links and heading anchors. Branch protection is a repository setting and is not part of this change.
- Docs: pull request template, CODEOWNERS, GOVERNANCE, SUPPORT, and feature-request and question issue forms with a contact-links config.
- Hook: `SKIP_ECHO=off` (also `0` or `false`) stops the SessionStart injection for a shell, a project (`env` in `.claude/settings.local.json` or `.claude/settings.json`), or a user; the skill stays available with `/skip-echo`. Unrecognized values keep the default. With `off` the hook does not load the policy module. The hook's only new input is this variable (#17).
- Diagnostics: `scripts/doctor.mjs` (`npm run doctor`) and the plugin command `/skip-echo:doctor` check Node.js, the manifest, the hook registration, the policy module, a dry run of the hook, `SKIP_ECHO`, and a standalone skill installed next to the plugin. `--debug-log <file>` reads a Claude Code debug log, such as one from `claude --debug-file <file> --init-only`, and reports whether the hook ran, whether the policy was delivered, and whether it ran twice. `--json` for machine output; exit code 1 on a failed check. Output contains no policy text and no home directory path (#18).
- Verified with Claude Code 2.1.296 on Linux through `--init-only` (no model call, isolated config): startup injection (3,905 characters), `SKIP_ECHO=off` from the shell, `--settings`, and project-local settings, `--scope local` disable, duplicate registration, and loading of `/skip-echo:doctor`. Interactive sessions and the other lifecycle sources remain untested; see docs/compatibility.md.
- Docs: `docs/troubleshooting.md` (activation checks, turning SkipEcho off at each scope, duplicate loading, Node.js, timeouts), README sections in English and Japanese, a doctor-output field in the activation issue form, and `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1, reports through GitHub only).
- CI: `claude plugin validate --strict commands`.
- Measurement: `scripts/echo-meter.mjs` (`npm run meter`) and the plugin command `/skip-echo:echo-meter` measure cross-turn repetition without a judge model: the share of each reply's prose made of word sequences (CJK: character sequences) already in earlier assistant turns, with the current user turn excluded and fenced code reported separately. `transcript` mode reads Claude Code session files or `--project`; `results` mode reads recorded eval outputs against their case histories and compares groups per case. Deterministic, offline, no network or model calls, and no conversation text printed without `--examples`. A re-analysis of the committed results is recorded in evals/results.
- Measurement: `scripts/measure-cost.mjs` (`npm run cost`) measures SkipEcho's input-token, cost and latency overhead from the usage Claude Code reports, with and without the plugin, with `SKIP_ECHO=off`, and with a duplicate standalone skill, over two-turn sessions; `--summarize` recomputes a saved record. First record (2026-10-13, Claude Code 2.1.296, `claude-sonnet-5-5`): about 1,330 extra input tokens per request, of which about 1,170 are the policy, 150 the listings, and 140 more for a duplicate standalone skill. README estimates are replaced by these measurements and a break-even statement (#6).
- Repository: removed an eval run directory and a replayed session transcript that had been committed by mistake under `evals/hard/`; both paths are gitignored, and the same result, with local paths removed, is kept in `evals/results/hard-check-2026-10-06.json`.
